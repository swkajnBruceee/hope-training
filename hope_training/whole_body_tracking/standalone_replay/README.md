# A3 RobotIOBackend standalone replay

This directory is a project-side CMake overlay. It does not edit the vendor deployment tree.

The AimRT/ROS interface generator must see an ASCII-only source path. If the
checkout path contains non-ASCII characters, create an ASCII symlink outside
the repository and configure through that symlink (the build directory can
also live outside the repository):

```bash
ln -s "$PWD/agibot/code_deployment/a3_deploy_example" /tmp/a3_deploy_ascii
source <ros-prefix>/setup.bash
export HAS_ROS2=1
```

Configure the vendor project through that path:

```bash
cmake -S /tmp/a3_deploy_ascii -B /tmp/a3_strike_sil \
  -DCMAKE_PROJECT_INCLUDE="$PWD/hope_training/whole_body_tracking/standalone_replay/a3_strike_replay_extension.cmake" \
  -DENABLE_A3_ROS_MSGS=ON -DENABLE_A3_AIMRT_BACKEND=ON
cmake --build /tmp/a3_strike_sil \
  --target a3_strike_robotio_replay -j2
```

The build environment must provide Eigen, a consistent ROS 2 installation with
`rosidl_typesupport_c`, the vendored `joint_msgs` generator dependencies, and
the AimRT dependencies used by `a3_deploy_example`, plus development headers
for zlib, ZeroMQ/cppzmq, msgpack, and nlohmann-json. The executable is emitted
beside the vendor deployment runtime binaries. Build success only verifies the
binary contract; it does not authorize starting the backend on a robot.

It consumes a canonical command NPZ generated by
`tools/build_a3_body_drive_command.py`, starts the official `RobotIOBackend`,
waits for an aligned six-channel 31-DOF state, sends an explicit 150-tick
PD-STAND phase, then replays each command timestamp. It writes:

- `raw_state.csv`: logical state, data-ready and sync-ready clocks, q/dq/tau;
- `command.csv`: 50 Hz command publication clock and payload timestamps.

Command NPZ files must use stored (uncompressed) ZIP entries. The builder
enforces this because the vendor `cnpy` reader miscounts Unicode
`joint_names` elements in a compressed NumPy stream; it also writes that field
last so the numeric command arrays remain portable to the runner. The
canonical payload hash is unchanged by the container encoding.

Convert raw evidence before qualification:

```bash
python tools/convert_a3_robotio_replay.py \
  --raw-state-csv <run>/raw_state.csv --command-csv <run>/command.csv \
  --output <run>/raw_state_sidecar.npz
```

The runner deliberately does not fabricate racket FK or ball metrics. Capture
official-model task samples in a second terminal before starting the runner:

```bash
source tools/setup_a3_mujoco_sim_env.sh
python tools/record_a3_racket_task_samples.py \
  --output <run>/actual_task_samples.npz \
  --duration-s <replay-duration-plus-tail>
```

The recorder waits for the 151st waist command: the runner's documented 150
PD-STAND ticks are ignored and that next command becomes `timestamp_s=0`.
It pairs `pelvis_pose` and `right_racket_pose` from the official A3 MuJoCo
model, derives world linear velocity from racket poses, then rotates position,
velocity, and the documented local `+Y` red-face normal into the pelvis base
frame.  Pass `--target-spec` to embed the immutable target hash and mount ID;
doing so records provenance but does not itself certify a replay.

After a target has been independently reviewed and frozen, an already-running
local MuJoCo simulator can be used for the ten-repeat SIL harness:

```bash
tools/run_a3_sil_qualification_repeats.sh \
  --executor-contract contracts/a3_t2d5_body_drive_fixed_stand_diag_v1/executor_contract.json \
  --target-spec <reviewed-target-spec.json> --command <canonical-command.npz> \
  --runner <path-to-a3_strike_robotio_replay> \
  --backend-config <path-to-a3_aimrt_config.ros2_mujoco_sim.yaml> \
  --out artifacts/pilots/<episode>/sil_repeats
```

The output directory must be fresh. The harness rejects fewer than ten repeats
and cannot be used with a review candidate in place of an immutable target.
